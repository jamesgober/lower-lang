# lower-lang v0.2.0 — Foundation: Syntax Trees Become HIR

**The foundation, and most of the road to 1.0.** v0.2.0 turns the scaffold
into a working lowering stage: give it a lossless syntax tree and a mapping
that says what the language's constructs mean, and it builds validated HIR
with an origin on every node, hygienic templates for sugar, explicit budgets,
and every problem in half-typed code reported instead of fatal. Templates,
budgets, and benchmarks, planned for 0.5, are in this release; only the
textual template syntax waits for hir-lang 0.5.

## What is lower-lang?

The L3 stage of LexerSketch (SEMA tier of the `-lang` family): the step from a
concrete syntax tree to the HIR that every forged language shares, so one
resolver, one type checker, and one evaluator serve every language. A
language does not write a lowering pass; it declares its semantics as data —
the LSF2 `[semantics.bind]`, `[semantics.lower]`, and `[semantics.ops]`
sections, mirrored here as a Rust `Mapping`.

## What's new in 0.2.0

### `lower` — one call

```rust
use hir_lang::OpKind;
use intern_lang::Interner;
use lower_lang::{lower, Arch, MappingBuilder, OpSpec, Pick, TokenRole};
use syntax_lang::{Element, Node, Span, Token, TokenKind};

#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord)]
enum K { File, Add, Num, Plus }
impl TokenKind for K {}

let mut b = MappingBuilder::new();
b.node(K::File, Arch::Module { name: Pick::Absent, items: Pick::Nodes });
b.node(K::Add, Arch::binary());
b.token(K::Num, TokenRole::Int);
b.binary_op(K::Plus, OpSpec::Op(OpKind::Add));
let mapping = b.build()?;

let tok = |k, s, e| Element::Token(Token::new(k, Span::new(s, e)));
let add = Node::new(K::Add, vec![tok(K::Num, 0, 1), tok(K::Plus, 1, 2), tok(K::Num, 2, 3)]);
let file = Node::new(K::File, vec![Element::Node(add)]);
let out = lower(&file, "1+2", &mapping, &mut Interner::new()).expect("within budget");
assert!(out.problems.is_empty());
# Ok::<(), lower_lang::MappingError>(())
```

`Lowerer` adds a `Budget`, a compilation unit, and a `Labeler` for trees whose
grammar names its fields.

### The archetype catalogue

`Arch` covers binders (let/const/var with mutability and hoisting, parameters
with by-reference, defaults, variadics, named-only and positional-only
markers, receivers, pattern bindings, captures, imports), scopes and
namespaces (by context), declarations (functions, records and unions, sums,
interfaces, classes with bases, interfaces, mixins, and static members, impls,
aliases, associated types, constants, globals, modules with top-level bodies),
control (if, match, loop, labelled break/continue, return, defer,
try/catch/finally, throw, yield, await, spawn), expressions (literals, paths
with roots and qualified selves, calls with named, spread, and place
arguments, method calls, fields, indexing, dynamic members, `$$var`, `$a[]`,
tuples, arrays, maps, record literals, casts, borrows, closures, operators),
and every HIR pattern and type form. The same node lowers by context: a tuple
is a tuple expression, a tuple pattern, or a tuple type; a call in a pattern
is a constructor pattern.

### Fields by label, kind, or position

A field is a `Pick`: a host label (LSF2 `name:expr`, through `Labeler`), a
kind, a position, or a neighbour (`After`, `Before`, `Between`). lang-forge
1.x trees have no labels yet, so the worked example uses kind picks. When
half-typed code makes two fields pick the same child, the child is lowered
once and an `AmbiguousChild` problem says so.

### Operators with their policies

`OpSpec` maps an operator token to an OPS op (with the language's overflow,
division, shift, and conversion policies in exactly the fields the op
consults, or an exact policy), compound or plain assignment, a borrow, a
dereference, `await`, a template (`&&`, `||`, `??`, `x++`, `?`), a host
function (Mox's `.`), or a named intrinsic.

### Hygienic templates

A `TemplateBuilder` builds a typed, HIR-shaped template with expression,
pattern, type, statement-list, argument-list, and label holes. Every
instantiation records its own HIR expansion; the binders and labels it
introduces are fresh, carry that expansion's mark, and are referenced by
binder id, so a user's `$it` and the `for-each` template's `it` never meet.
Free names a template writes carry the mark too; host symbols are
pre-resolved. Holes used twice are copied; templates may apply earlier
templates (acyclic by construction, depth-budgeted). The `templates` module
has `while`, `do-while`, C `for`, `for-each`, `&&`, `||`, value-returning
`and`/`or`, `??`, `?`, and `x++`.

### Half-typed code is normal input

Syntax-error nodes, unmapped kinds, unsupported constructs, missing parts,
wrong contexts, unknown operators and labels, bad literals and escapes, and
spans outside the source each become an HIR error form plus a `Problem` with
its span; hir-lang's `finish_lenient` repairs and reports the rest. Lowering
fails only when a budget, the interner, or hir-lang's arenas run out.

### Dynamic-language semantics

`LangPolicy` sets OPS policies, effect inference (`Inferred`: a `yield` makes
a generator; `Always`: any function may throw), PHP implicit locals (an
assignment declares the variable for the whole function, except parameters,
globals, statics, and captures), place arguments (every place argument is
passed as a place, for by-reference parameters), and how bare identifiers in
match arms lower.

## Tests and verification

- **End to end.** A calc language forged by lang-forge 1.0.1 from an `.lsf`
  schematic: program → CST → lower → hir-lang validation → a resolver that
  resolves every local reference by HIR's scope rules. Every prefix of the
  program (typing it one character at a time) lowers to valid HIR.
- **Mox-flavoured trees** built with syntax-lang's `Builder`: `foreach`
  hygiene next to a user `$it`, by-reference parameters and place arguments,
  implicit locals, `global`/`static`, `use (&$x)` captures, `->` members
  (static and dynamic), `$$var`, `$a[]`, a class with a mixin and a static
  property, try/catch (two types)/finally, generator inference, map literals,
  string escapes.
- **Property tests** (per run): 512 random trees over a mapping with most
  archetypes and every template, under two language policies — valid HIR,
  in-source origins and problems, hygiene after a resolver runs, determinism
  across two runs; 512 trees with arbitrary spans; 512 node budgets; 256 calc
  token soups parsed by lang-forge; and 256 random calc programs whose direct
  evaluation (the reference) must equal the evaluation of their lowered HIR.
  A 20-run soak (40,960 cases in all, fresh random seeds) found nothing.
- **Depth.** A 100,000-deep operator chain lowers on the default test stack.

## Benchmarks

`cargo bench --bench bench`, Windows 11, x86_64, release profile, library
only (trees parsed outside the measurement; validation included):

| Benchmark | Input | Time | Throughput |
|---|---|---:|---:|
| `calc/100k` | 177,101 elements | ~12.6 ms | ~14 M elements/s |
| `calc/1m` | 1,771,001 elements → 748,002 HIR nodes | ~157 ms | ~11 M elements/s |
| `templates/100k` | 93,001 elements, mostly templates | ~12 ms | ~7.8 M elements/s |
| `templates/1m` | 930,001 elements | ~129 ms | ~7.2 M elements/s |
| `deep/100k_prefix_chain` | 200,004 elements | ~37 ms | ~5.4 M elements/s |

Of `calc/1m`, hir-lang's validation is about 20 ms and its node building
about 30 ms; the rest is lowering's traversal, interning, and dispatch. The
figures predate the release's final change (the `AmbiguousChild` check), whose
cost an interleaved A/B on a loaded machine bounds at about 10%; the release
gate re-measures.

## Dependency wiring

`syntax-lang` 1, `hir-lang` 0.3, and `intern-lang` 1 are wired. `span-lang`
arrives through them (0.4). `macro-lang` is deliberately not wired: HIR-level
hygiene is hir-lang's own expansions and marks. `diag-lang` is not wired:
converting a `Problem` to a diagnostic is the host's one line. `lang-forge`
is a dev-dependency only. Recorded in `dev/ROADMAP.md`.

## Breaking changes

**None.** v0.1.0 had no public API.

## Known limitations

- lang-forge 1.x trees carry no field labels, so mappings over them use kind
  and position picks; positional picks can misread half-typed code (the
  `AmbiguousChild` check catches the aliasing case, not every misreading).
- Textual templates wait for hir-lang 0.5's textual syntax.
- Not yet lowered: PHP trait conflict rules, nested import trees, string
  interpolation, attributes, recursive-closure self binders, foreign
  functions. All recorded in `dev/ROADMAP.md`.
