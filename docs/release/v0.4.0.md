# lower-lang v0.4.0 — Templates as Text, hir-lang 0.4, Resolver in the Loop

**The shortest path to "Mox programs print".** Two things stood between the
LexerSketch Demo (G3) and Mox's `echo`, `print`, `&&`, `||`, and `++$i`: the
semantics layer could not use the sketch's template texts (LSF5105), and
lower-lang was on hir-lang 0.3 while resolve-lang 0.4 and typeck-lang 0.3 are
on 0.4, so the chain could not be combined. v0.4.0 removes both. Template
text is parsed by lower-lang itself (decision D26), ahead of hir-lang 0.5;
lower-lang moves to hir-lang 0.4 and lowers its new forms; and compound
assignment with PHP's non-OPS operators evaluates its place once. The tests
now resolve what they lower through resolve-lang 0.4.

## What is lower-lang?

The L3 stage of LexerSketch (SEMA tier of the `-lang` family): the step from a
concrete syntax tree to the HIR every forged language shares. A language does
not write a lowering pass; it declares its semantics as data (a `Mapping`),
and lower-lang builds validated HIR with an origin on every node.

## What's new in 0.4.0

### Templates as text

```rust
use lower_lang::{HoleKind, MappingBuilder, OpSpec, Template};

// The lazy path: one template.
let and = Template::parse("bool_and", "if ${lhs} { not(not(${rhs})) } else { false }")?;
assert_eq!(and.hole(1), Some(("rhs", HoleKind::Expr, false)));

// LSF2's `[semantics.templates]`, registered in document order.
let mut b = MappingBuilder::<u8>::new();
let echo = b.parse_template("echo", "extern:mox.echo(${...values})")?;
let inc = b.parse_template("pre_increment", "let_place p = ${place} in p = add(p, 1)")?;
b.prefix_op(1, OpSpec::Template(inc));
b.template_node(2, echo, &[lower_lang::Pick::All]);
assert!(b.build().is_ok());
# Ok::<(), Box<dyn std::error::Error>>(())
```

`Template::parse` and `MappingBuilder::parse_template` parse the template
subset of HIR's textual syntax (HIR spec §20, LSF2 §15.8) straight into the
template AST that `TemplateBuilder` builds. Nothing is substituted as text:
holes are filled with already-lowered HIR when the template is instantiated.

- **Holes** take their kind from where they are written: `${name}` as an
  expression, a pattern, a type, or a label; `${...name}` as an argument
  list or a statement list; `${name?}` optional; `${name?=<literal>}` with a
  default.
- **Template binders and labels** are written without ids (`let old = …`,
  `'outer loop`) and are fresh and hygienic per instantiation.
- **Free names** are explicit: `extern:mox.iter` (a host symbol),
  `global:a::b` (resolved at the template's definition site); any other
  unbound name is an error, so a typo cannot capture a user name.
- **Operations** by their OPS name: `add(a, b)` takes the language's
  policies, `add<overflow=wrap>(a, b)` exactly these; conversions name their
  target (`int_cast<i32>(x)`).
- **`apply:name(…)`** names a template registered before, or a built-in by
  its LSF2 name (`coalesce`, `while`, …).
- The rest of the subset: blocks, `let`, `if`/`else`, `loop` with
  `[step: …]`, `break`/`continue`, `match` with guards, closures with capture
  modes, tuples, arrays, calls, methods, fields, indexes, `return`, `throw`,
  `await`, `spawn`, `defer`, keyed `yield`, `yield from`, `let_place`, union
  and intersection types.

Every refusal is `TemplateError::Syntax { at, error }`: the byte range of the
text and a `SyntaxError` (21 kinds). The parser is recursive descent with a
nesting cap (`MAX_TEMPLATE_DEPTH` = 32) and a length cap
(`MAX_TEMPLATE_TEXT` = 1 MiB), never panics, and is never quadratic. Every
`[semantics.templates]` text of `mox.lsf` parses, the multi-line
`yield_from` included.

### Places evaluated once

```rust
use lower_lang::{templates, MappingBuilder, OpSpec};

let mut b = MappingBuilder::<u8>::new();
let concat = b.name("mox.concat");
let pow = b.name("mox.pow");
let coalesce = b.template(templates::coalesce())?;
b.binary_op(1, OpSpec::CompoundIntrinsic(concat))   // .=
    .binary_op(2, OpSpec::CompoundIntrinsic(pow))   // **=
    .binary_op(3, OpSpec::CompoundTemplate(coalesce)); // ??=
assert!(b.build().is_ok());
# Ok::<(), lower_lang::MappingError>(())
```

`$a[f()] .= "!"` lowers to `let_place p = $a[f()] in p = mox.concat(p,
"!")`: `f` is called once. The alias is a `Place` binder carrying a
`compound` desugaring mark. The same holds for templates written with
`let_place`; the sketch's current `pre_increment`
(`{ ${place} = add(${place}, 1); ${place} }`) evaluates its place three times,
and its `let_place` form (`let_place p = ${place} in p = add(p, 1)`) once.
The tests measure both on `++$a[f()]`. The built-in `post_increment` now
uses `let_place` too.

### hir-lang 0.4 forms

- `Arch::Yield { key, value }` (`yield $k => $v`; a key without a value
  yields `null`) and `Arch::YieldFrom`.
- `Arch::UnionTy` and `Arch::IntersectionTy` (PHP `int|string|null`,
  `A&B`), normalized by hir-lang (sorted, flattened, repeats dropped).
- `TemplateBuilder::yield_kv`, `yield_from`, `let_place`, `union_ty`,
  `intersection_ty`.
- `pow` as a compound op; `not` is logical, `bit_not` the complement.

### Resolver in the loop

resolve-lang 0.4 is a dev-dependency. The Mox tests resolve under
`Policy::php()`: the Mox program in `tests/textual.rs` (`&&`, `||`, `++`,
`--`, `echo`, `print`, `.=`, `??=`, `**=`, `yield from`, keyed `yield`, a
union parameter type) lowers with no problems and resolves with no
diagnostics, every path resolved. The random-tree properties resolve every
result under the lexical or PHP policy, check hygiene, and check that
resolution is deterministic.

### Fixed

`Arch::RefAssign` was never finished: its operands were lowered and dropped,
which left orphaned HIR (LexerSketch 0.3.0 worked around it by marking
`ref_assign` pending). It now lowers to `Expr::RefAssign`.

## Tests and verification

- **Parse equals builder** (`src/text/tests.rs`, 512 cases per run): random
  templates over every form, rendered as text and built with
  `TemplateBuilder` side by side; the parsed template equals the built one in
  a canonical form (binders and labels by first appearance, holes by
  declaration).
- **Hostile text**: 512 arbitrary strings and 512 token soups of the
  template vocabulary per run, never a panic; 16 nesting forms past the cap
  on a 512 KiB thread, each a `TooDeep` error; a text one byte over the cap
  is `TooLong`.
- **Every error kind** has a test; most pin the byte range.
- **Mox end to end** (`tests/textual.rs`): every template text of the
  sketch parses and registers; lowering validates and resolves; place-once
  counts (index expressions, calls); the inline `[semantics.lower]` form.
- **hir-lang 0.4 forms** (`tests/hir_0_4.rs`): unions and intersections,
  keyed yields, `yield from`, the four compound specs, a missing operand, the
  `ref_assign` fix, `int_cast` under `promote`, lenient repair reporting a
  duplicate binding at every repeat.
- **Random trees** now reach `let_place`, unions, intersections, keyed
  yields, and `yield from` (checked by a generator-reach test).

## Dependency wiring

- `hir-lang` 0.4 (was 0.3): one `hir_lang` shared with resolve-lang 0.4 and
  typeck-lang 0.3.
- `resolve-lang` 0.4: dev-dependency, from the registry.
- Unchanged: `syntax-lang` 1, `intern-lang` 1; `lang-forge` 1.0.1 as a
  dev-dependency. No third-party runtime dependency; the template parser is
  our own.

## Breaking changes

- hir-lang 0.4 (output types).
- `Arch::Yield` gains `key`.
- `templates::post_increment()` uses `let_place`.
- New `OpSpec`, `Arch`, and `TemplateError` variants (all
  `#[non_exhaustive]`).

Details and a migration table in the CHANGELOG.

## Known limitations

- The template parser implements HIR spec §20's template subset as this
  release reads it; hir-lang 0.5 ships the full textual parser, and the two
  are checked against each other then (D26). There is no template printer
  yet (hir-lang 0.5 owns the round-trip printer).
- String literal patterns, tuple types, and label holes on plain blocks are
  not in the text syntax (the builder has no string patterns or tuple types
  either).
- A hole after `break` is a label only if it is already a label hole.
- `??=` through `coalesce` assigns the place even when it is not null (the
  same value back); a language for which that is observable needs its own
  template.
- The `yield_from` text in `mox.lsf` yields `(k, v)` tuples with automatic
  keys; `yield k => v` (or simply `yield from ${from}`, now native) keeps the
  inner generator's keys.
