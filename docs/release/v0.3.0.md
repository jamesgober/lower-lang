# lower-lang v0.3.0 — PHP and Python Semantics

**What the Mox demo needs.** v0.3.0 closes what LexerSketch's ISSUES ledger
lists as P15: the lowering behaviour PHP (and so Mox) and Python need before
the Mox Demo milestone. `foreach` and `catch` variables outlive their
construct as PHP's do; strings delivered in segments become one string;
numbers are decoded by a per-language table; operators can be keyed by text;
group `use` declarations, trait `insteadof`/`as` rules, and attributes lower
to their HIR forms. Each new behaviour is held to a property test against an
independent reference.

## What is lower-lang?

The L3 stage of LexerSketch (SEMA tier of the `-lang` family): the step from a
concrete syntax tree to the HIR every forged language shares. A language does
not write a lowering pass; it declares its semantics as data (a `Mapping`),
and lower-lang builds validated HIR with an origin on every node.

## What's new in 0.3.0

### PHP's preset

```rust
use hir_lang::Overflow;
use lower_lang::{LangPolicy, LegacyOctal, MappingBuilder};

let mut b = MappingBuilder::<u8>::new();
b.policy(LangPolicy::php());
let php = LangPolicy::php();
assert_eq!(php.overflow, Overflow::Promote);
assert!(php.function_scoped_bindings && php.implicit_locals);
assert_eq!(php.literals.legacy_octal, LegacyOctal::Octal);
```

`LangPolicy::php()` bundles what Mox needs: integers promote to float,
any function may throw, a `yield` makes a generator, assignment declares a
variable for the whole function, place arguments pass by place, `foreach`
and `catch` variables are function-scoped, and numbers use PHP's spelling.

### Function-scoped `foreach` and `catch`

With `function_scoped_bindings`, every pattern hole of a template (the key
and value of `for_each`) and every `catch` name is declared once for the
function. The pattern binds hygienic temporaries, each with its own `Desugar`
expansion named `hoist`, and an assignment to the function-scoped name runs
right after the pattern matches, so `foreach ($m as [$a, [$b, $c]])` works
for any shape and `$v` is readable after the loop. A by-reference binding
(`as &$v`) cannot be expressed as an assignment; it is reported as
`CannotHoist { reason: ByReference }` and stays scoped. A hoisted `let`
(JavaScript `var`) with a destructuring pattern now uses the same mechanism.

### Interpolated strings and heredocs

`Arch::Interp { parts, close, join }` takes a string as the lexer delivers
it: `StrPart` text tokens between embedded expressions (`"Hello {$name}"`,
`"$name"`, `"{$a['k']}"`). The pieces are joined by a `Join`: a left fold of
a two-argument host function (`mox.concat`, PHP's `.`), one call with every
piece, or a template. A heredoc names its closing marker with `close`; the
marker's indentation leaves every line (PHP 7.3), a line indented less (or
starting with an embedded expression) is reported, and the final newline is
dropped. Empty text pieces are left out of
the join. The CST shapes Mox's mapping expects are documented in
`tests/support/mox.rs`.

### The literal decoding table

- `TokenRole::RawStr`: Rust `r#"…"#`, Python `r'…'` and triple-quoted raw
  strings, verbatim.
- `TokenRole::Heredoc(Escapes)`: a heredoc (`Standard`) or nowdoc (`None`)
  as one token, with PHP 7.3 indentation stripping.
- `Literals { separators, legacy_octal, hex_floats }`: `_` anywhere, only
  between digits (PHP 7.4+), or never; `0777` decimal, octal, or an error
  (Python 3); hex floats (`0x1.8p3`), correctly rounded.
- Integers beyond 64 bits follow `LangPolicy::overflow`: under PHP's
  `Promote` anything above `i64::MAX` is the nearest float; otherwise
  decimal, binary, octal, and hex values are exact big integers.

### Operators by text

`prefix_op_text`, `binary_op_text`, and `postfix_op_text` key operators by the
token's text, for lexers that give every operator one kind. A kind entry wins
over a text entry.

### Use trees, trait rules, attributes

- `Arch::UseTree` flattens `use a::{b, c::{d as e}, self, *}` and PHP
  `use App\Models\{User, Post as P}` into one HIR import per leaf,
  iteratively; an empty group imports nothing.
- `Arch::MixinUse` gains `rules`; `Arch::MixinRule` lowers `T::m insteadof
  U` and `T::m as protected n` to hir-lang's `MixinRule`.
- `Arch::Attr` and `Arch::AttrArg` attach attributes to the HIR node of the
  construct they annotate (items, parameters, fields, variants, statements,
  expressions). PHP's `#[A, B]` group splices. Arguments must be literals or
  names (`AttributeArgument` otherwise); an attribute on a construct without
  an HIR node is a `MisplacedAttribute` problem.

## Tests and verification

- **Property tests against references** (`tests/semantics.rs`, 512 cases
  each per run unless noted): random nested `var`/`foreach`/`catch` with
  random destructuring and by-reference bindings against a scope model;
  interpolation against a reference concatenation (escapes, adjacent pieces,
  lone expressions); heredoc indentation against PHP 7.3's rule; integer
  literals of every radix and separator spelling under the default and PHP
  tables against a `u128` reference; nested use trees against a recursive
  flattener.
- **Random trees** (`tests/properties.rs`): the existing properties (valid
  HIR, origins, hygiene after resolution, determinism, budgets) now run under
  three policies including `LangPolicy::php()`, over a mapping with the new
  archetypes, and a check that the generator reaches attributes (attached and
  misplaced), use trees, interpolation joins, and decoded texts.
- **Mox** (`tests/mox.rs`): interpolation, heredocs, function-scoped
  `foreach`/`catch`, trait rules, group `use`, attributes, PHP number
  literals, and the `foreach` hygiene test now under PHP scoping.
- 40 extra randomized runs of the property suites with fresh seeds were
  clean.

## Dependency wiring

Unchanged: `syntax-lang` 1, `hir-lang` 0.3, `intern-lang` 1; `lang-forge`
1.0.1 as a dev-dependency. `resolve-lang` is **not** a dev-dependency: its
0.3.0 (the release that resolves case-folded PHP names and trait rules) is
not on crates.io yet, and the family rule is registry versions only, never
path dependencies. The tests resolve locals with a small resolver over
hir-lang's `lookup_local`; wiring resolve-lang 0.3 into the Mox tests is the
first item for 0.4.

## Breaking changes

- `Arch::MixinUse` has a second field, `rules`.
- A hoisted `Let` with a destructuring pattern is now hoisted.
- Integers beyond 64 bits follow the overflow policy (floats under
  `Promote`; exact big integers for every radix otherwise).
- The default literal table accepts hex floats.
- Nodes mapped as `Attr` are invisible to picks.

Details in the CHANGELOG.

## Known limitations

- Attributes are found only as direct children (or in an all-attribute
  container) of the annotated node; their names are kept as written, not
  resolved.
- By-reference `foreach` bindings stay scoped to the loop (reported).
- Non-decimal big integers convert to at most 1,024 decimal digits.
- Textual templates still wait for hir-lang's textual syntax.
