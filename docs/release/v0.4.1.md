# lower-lang v0.4.1 — Receivers, Break Levels, Per-Archetype Modifiers, Conditional Templates

**Mox classes run.** bcgen-lang 0.4 compiles classes, but a Mox method could
not run end to end because lower-lang gave it no receiver parameter: LSF2's
`implicit_receiver` was pending. v0.4.1 adds it, and closes the other pending
LSF2 items the next Mox release needs: numeric `break N` / `continue N`,
per-archetype modifiers (`...` as a rest parameter and as a spread argument),
conditional templates (the `include` family), and a default visibility for
class members (PHP methods are public without a keyword). It is an additive patch: no
existing signature changes, and nothing changes until a mapping asks for it.

## What is lower-lang?

The L3 stage of LexerSketch (SEMA tier of the `-lang` family): the step from a
concrete syntax tree to the HIR every forged language shares. A language does
not write a lowering pass; it declares its semantics as data (a `Mapping`),
and lower-lang builds validated HIR with an origin on every node.

## What's new in 0.4.1

### The implicit receiver (`$this`)

```rust
use lower_lang::{BreakLevels, LangPolicy, MappingBuilder};

let mut b = MappingBuilder::<u8>::new();
let mut mox = LangPolicy::php();
mox.implicit_receiver = Some(b.name("this")); // [semantics.policy] implicit_receiver = "this"
mox.break_levels = BreakLevels::Numeric;      // [semantics.policy] break_levels = "numeric"
mox.default_member_visibility = hir_lang::Vis::Public; // [semantics.policy] default_visibility = "public"
b.policy(mox);
assert!(b.build().is_ok());
```

- Every method of a class, mixin, or interface that is not `static` and has
  no explicit receiver gets a first HIR parameter of kind `Receiver` binding
  `this`, which is how bcgen-lang 0.4 tells an instance method from a static
  one. Static methods, functions that are not members, and `impl` members
  are unchanged.
- The receiver is an ordinary user name: the body sees it, an assignment to
  it never declares an implicit local, and template binders (marked with
  their expansion) never capture it.
- Closures follow PHP. A `function () use (...)` closure in a method gets a
  by-value capture of `$this` (unless it captures it itself); an `fn () =>`
  closure reaches it through implicit captures; a `static` closure, and
  anything nested in one, has none, and reading `$this` there is the new
  `ProblemKind::NoReceiver`.

End to end through resolve-lang 0.4, bcgen-lang 0.4, and bvm-lang
2.0.0-alpha.4 (`tests/receivers.rs`, `examples/classes.rs`):

```php
class A { public $x;
  public function __construct($x) { $this->x = $x; }
  public function get() { return $this->x; } }
class B extends A { public $y;
  public function __construct($x, $y) { parent::__construct($x); $this->y = $y; }
  public function sum() { return $this->get() + $this->y; } }
$b = new B(2, 3);
echo $b->sum();   // 5
echo $b->x;       // 2
```

`new B(...)` goes through the sketch's `new_object` template
(`extern:mox.new(${class}, ${...args})`), whose class operand resolve-lang
0.4.1 resolves under `Policy::php()`; `new $name(...)` works too. Static
methods through `self::` and `K::`, mixin (trait) methods, closures and arrow
functions over `$this`, and nested closures run the same way.

### Default member visibility

`LangPolicy::default_member_visibility` (LSF2 `default_visibility`) is the
visibility of a method, property, static, or constant of a class, mixin, or
interface written without a visibility keyword. PHP and Mox set `Public`;
the default `Private` keeps 0.4.0's behaviour. With it, a class written with
no `public` anywhere runs end to end, `parent::__construct(1)` included.
Declarations outside class bodies, `impl` members, and members with a keyword
are unchanged.

### Numeric break levels

`BreakLevels::Numeric` lowers PHP's `break 2` / `continue 2` to a labelled HIR
jump to the second enclosing loop of the function. The target keeps its own
label, or gets a hygienic one made only when a jump needs it. `Arch::Loop`
nodes and template nodes whose template has a label hole (`while`,
`do_while`, `c_for`, `for_each`) count as loops; closures and functions start
a new count. `break 0`, a non-literal level, or more levels than loops is the
new `ProblemKind::BreakLevel { level, loops }`, and the jump becomes an error
expression.

### Per-archetype modifiers

```rust
use lower_lang::{MappingBuilder, Modifier};

const DOTS: u8 = 7; // `...`
let mut b = MappingBuilder::<u8>::new();
b.modifier_in(DOTS, "param", Modifier::Rest)    // function f(...$xs)
    .modifier_in(DOTS, "arg", Modifier::Spread); // f(...$xs)
let m = b.build()?;
assert_eq!(m.modifier_in(&DOTS, "arg"), Some(Modifier::Spread));
# Ok::<(), lower_lang::MappingError>(())
```

LSF2's `"..." = { param = "rest", arg = "spread" }`: the archetype names are
LSF2's `arch` names (`Arch::lsf_name`). Inside its archetype the entry wins
over a plain `modifier` entry. `Spread` on a `map_entry` (`[...$a]`) is
reported (`Unsupported`): HIR has no spread entry in map and array literals,
and 0.4.0 silently lowered `[...$a]` as `[$a]` when the marker was a plain
`Spread` modifier.

### Conditional templates

`MappingBuilder::template_node_when(kind, when, template, holes)` is
`node_when` for templates (LSF2's conditional `{ when = …, template = … }`
alternatives, ISSUES P40): Mox's `include`, `include_once`, `require`, and
`require_once` are one node kind lowered through four templates.

### Keyword type names

In a type, a role-less keyword (`array`, `callable`) or a `null` / `false` /
`true` token whose text is a registered `type_name` is that type. HIR has no
precise term for any of them, so Mox maps them to `any`.

## Tests and verification

- **Receivers, reference model** (`tests/receivers.rs`, 256 cases per run):
  random classes with static and instance methods holding random nests of
  closures (static or not, explicit or implicit captures, `use ($this)` or
  not) and named functions, all reading `$this`. Checked: receivers per
  method, which closures capture `$this`, which reads are `NoReceiver`, that
  every resolved `$this` names a receiver or a capture, valid HIR, and
  determinism.
- **Break levels, reference model** (`tests/break_levels.rs`, 256 cases per
  run): random nests of loops, closures, and `break`/`continue` with levels
  0 to 5. Every jump is checked against a reference that counts loops per
  function, as the targeted loop's label, a plain jump, or the exact
  problem. Only targeted loops get labels.
- **End to end on bvm-lang:** classes (constructor, getter,
  `parent::__construct`, `new C` and `new $name`, no visibility keywords
  under `default_member_visibility = Public`), static methods, mixin methods, closures over
  `$this`, nested loops with `continue`, `continue 2`, `break 2`, and
  `break 1`, rest parameters and spread arguments.
- **Hygiene:** a template binding its own `this` around user code; each
  `this` resolves to its own binder.
- **Hostile and edge cases:** every bad level (0, too many, a variable, a
  float, a literal beyond `u64`, inside a closure); level spellings
  (`(2)`, `0x2`, `0b10`, `02`); 5,000 nested loops with `break 5000` on a
  256 KiB stack; foreign `NameRef`s; unknown archetype names; duplicate
  per-archetype entries; hole counts of conditional templates.
- **Random trees** run under a fourth policy with every 0.4.1 feature on;
  a generator-reach test checks that they reach receivers, bad levels,
  spread entries, and conditional templates.

## Benchmarks

`cargo bench --bench bench`, Windows 11, x86_64, release profile, library
only, while other builds shared the machine (run-to-run noise up to about
20%):

| Benchmark | Input | Time | Throughput |
|---|---|---:|---:|
| `oop/100k` (new) | 114,400 elements: 520 Mox classes with receivers, closures over `$this`, `continue 2` / `break 2`, rest and spread, `include_once` | ~7.8 ms | ~14.6 M elements/s |
| `oop/1m` (new) | 1,144,000 elements | ~97 ms | ~11.8 M elements/s |
| `oop_off/100k` (new) | the same trees with the receiver and numeric levels off | ~6.9 ms | ~16.6 M elements/s |
| `oop_off/1m` (new) | 1,144,000 elements | ~91 ms | ~12.6 M elements/s |

The receivers, captures, and labels cost what they build: `oop` is about 7%
(1m) to 13% (100k) slower than `oop_off`, which lowers the same trees into
fewer HIR nodes. Mappings that do not use the 0.4.1 features pay nothing
measurable: interleaved A/B runs of the 0.4.0 and 0.4.1 code in one session
gave `calc/100k` +1.3% and -2.1%, `templates/100k` -3.2% and -1.6%, none
significant (p > 0.05); `php/100k` measured -2.9% against the 0.4.0
baseline (p = 0.09). The other groups are unchanged in code path and were
not re-measured beyond one noisy run.

## Dependency wiring

- `bcgen-lang` 0.4 and `bvm-lang` `=2.0.0-alpha.4`: new dev-dependencies
  (registry), to run lowered Mox end to end. Not runtime dependencies. One
  `hir_lang` 0.4 in the tree.
- Unchanged: `syntax-lang` 1, `hir-lang` 0.4, `intern-lang` 1;
  `lang-forge` 1.0.1 and `resolve-lang` 0.4 as dev-dependencies (the tests
  need resolve-lang 0.4.1, which `"0.4"` selects, for `new C`). No
  third-party runtime dependency.

## Compatibility

No breaking change. New: three `LangPolicy` fields (`#[non_exhaustive]`
struct), `BreakLevels`, `MappingBuilder::modifier_in` and
`template_node_when`, `Mapping::modifier_in`, `Arch::lsf_name`,
`ProblemKind::{BreakLevel, NoReceiver}` and
`MappingError::{UnknownArchetype, UnknownName}` (both enums
`#[non_exhaustive]`). `LangPolicy::php()` is unchanged: it does not turn on
the receiver, numeric levels, or public members. Behaviour a 0.4.0 mapping can notice is listed
in the CHANGELOG ("Changed"): each was an error or a silent miscompile before.

## Known limitations

- `[...$a]` is reported, not lowered (needs an HIR spread entry).
- `null`, `false`, `true`, `array`, `callable` have no precise HIR type;
  `self` / `static` / `parent` in a type position are not lowered as types.
- PHP's `switch` is a loop for `break N`; Mox lowers `switch` through a hook,
  so it does not count here.
